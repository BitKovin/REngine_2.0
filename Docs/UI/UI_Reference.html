UI System Reference

Markup (XML), styles (a CSS dialect), text, motion, menus and tooling of the engine's UI. Built from the game's uidb.json (engine build Nov 7 2026 20:28:12, game StealthAction): the tables are what the engine registered.

Core engine functionality, the same for every game. Kit the shared menu kit built on top of the core: pages, components and a theme. A game can use the core without the kit.

1. Overview Core

A screen is an XML file (structure and events) plus CSS files (look). C++ is only needed for logic: a class registered for a layout (code-behind) can set variables and classes, handle actions and react to menu events. Data flows one way: the game sets variables and classes, the markup shows them.

You writeWhere
Layouts, componentsGameData/ui/**/*.xml
StylesGameData/ui/**/*.css, or a <style> block in the XML
Text${KEY} in the markup, strings in the game's localisation files
LogicC++ code-behind (optional), registered with UI_REGISTER_CODE_BEHIND

Smallest useful page:

<root>
  <styles>
    <include src="GameData/ui/theme.css"/>      <!-- shared look, a separate .css file -->
    <style>                                     <!-- and/or styles only this file needs -->
      .menu { flow-children: down; gap: 12px; padding: 24px; }
    </style>
  </styles>
  <Panel class="menu">
    <Label text="Hello {name}"/>
    <TextButton text="${MENU_PLAY}" onactivate="Push('GameData/ui/play.xml')"/>
  </Panel>
</root>

Errors never pass silently: an unknown tag, attribute or malformed value is reported with file:line when the page loads. The VS Code extension shows the same problems while you type.

Coordinates. The UI is always 1080 units tall (width follows the aspect ratio). One UI unit (px) is one pixel of that target, whatever the window size. Legacy Ui* widgets can sit inside markup, but new work should use the tags below.

2. File structure Core

<root>
  <imports>                                         <!-- optional: component files this file uses from elsewhere -->
    <import src="GameData/ui/shared/Fancy.xml"/>
  </imports>
  <styles>                                          <!-- optional, applied in the order written -->
    <include src="GameData/ui/theme.css"/>
    <style> .row { height: 40px; } </style>
  </styles>
  <snippets>                                        <!-- optional: file-local templates (list rows, built from code) -->
    <snippet name="Row" params="index=0">
      <Label text="Item {index}"/>
    </snippet>
  </snippets>
  <Panel id="page">                                 <!-- exactly one top element: any tag, or <Component> -->
    ...
  </Panel>
</root>
  • Exactly one top element inside <root>: any tag, or a <Component> (Components).
  • Styles from <include> and <style> are applied in the order written, as one cascade. CSS files can @import each other (imports must come first in the file).
  • Escaping. XML rules apply: write &lt;, &gt;, &amp; in attribute values and text. This matters for rich text, whose tags must be escaped.
  • Braces. {name} is a variable; write {{ and }} for literal braces.
  • A page gets the class page when it is pushed on a menu stack, and the root gets :root.

Legacy elements

The older Ui* classes (UiImage, UiText, UiButton, UiVerticalBox…) can be placed in markup with their own anchor attributes (Position, Size, Origin…). They are positioned in the parent's content box, and styled only by size and position. Use them only for code that already exists.

4. Text and rich text Core

All text is drawn by <Label>. It uses signed-distance-field glyphs, so one font works at every size, and stroke, shadow and glow come from the same glyphs. A line is shaped and wrapped once and reused until its text, font, size, width or variables change.

Plain text

Text comes from text="…" or from the element's own text. Variables {x} and localisation keys ${KEY} are expanded first (see Variables). Without html="true" a < is just a character.

Rich text: html="true"

With html="true" the text may contain these tags. Tags nest, and an unclosed tag lasts to the end.

TagEffectExample
<b>…</b>bold&lt;b&gt;Warning&lt;/b&gt;
<i>…</i>italic&lt;i&gt;whisper&lt;/i&gt;
<color=#rrggbb>…</color>text colour (#rrggbbaa adds alpha)&lt;color=#ff4040&gt;red&lt;/color&gt;
<size=NN>…</size>font size in UI pixels for this run&lt;size=40&gt;BIG&lt;/size&gt;
<icon=action:NAME>the key / button image of an input action, for the last-used device&lt;icon=action:interact&gt;
<icon=img:PATH>an image from GameData, sized to the text&lt;icon=img:GameData/textures/ui/coin.png&gt;
<icon=…,valign=middle>vertical placement of either icon form: baseline (default, bottom on the baseline), middle (centred on the capital letters), top, bottom&lt;icon=action:jump,valign=middle&gt;
<Label html="true"
       text="Plain &lt;b&gt;bold&lt;/b&gt; &lt;i&gt;italic&lt;/i&gt; &lt;color=#ff4040&gt;red&lt;/color&gt; &lt;size=40&gt;big&lt;/size&gt;"/>
You must escape the angle brackets in XML. Inside an attribute, write &lt;b&gt; for <b>. A literal <b> in the element's body would be read as a child element, not as text.

Colour, size and style together

<Label html="true" style="font-size: 28px; width: 420px"
       text="&lt;color=#ffd24a&gt;&lt;b&gt;Critical!&lt;/b&gt;&lt;/color&gt; Hit for
             &lt;size=44&gt;&lt;color=#ff5030&gt;{damage}&lt;/color&gt;&lt;/size&gt; damage.
             Press &lt;icon=action:block&gt; to block."/>

Input icons that follow the player's device

<icon=action:NAME> asks the game's icon provider for the image of the key or button bound to the input action NAME, for the last used device (keyboard and mouse, gamepad, touch). When the player picks up a gamepad, every such icon in every label changes by itself. The same works as a separate element, <InputPrompt action="…"/>.

<!-- the key or button that triggers the action, for the device the player used last -->
<Label html="true" text="Press &lt;icon=action:interact&gt; to open, &lt;icon=action:attack&gt; to strike"/>

<!-- an image from GameData, sized to the text -->
<Label html="true" text="&lt;icon=img:GameData/textures/ui/coin.png&gt; x {coins}"/>

Rich text with variables

<!-- code: label->SetVar("hp", 42); label->SetVar("max", 100); -->
<Label html="true" text="&lt;color=#ff6060&gt;{hp}&lt;/color&gt; / {max}"/>

Details worth knowing

  • Icons are squares of 1.1 × the current font size on the baseline, with a gap of 0.1 em; they scale with <size>. For line breaking an icon is an unbreakable word.
  • Bold and italic use the font's own faces when they exist (see @font-face), otherwise the engine thickens or skews the glyphs.
  • Colours are #rrggbb or #rrggbbaa. Anything else is an error for that tag.
  • Size is in UI pixels and replaces the label's font-size for that run. It shrinks together with the label when text-overflow: shrink is used.
  • Unknown or malformed tags (<foo>, <color=red>) are drawn literally and logged once as a warning.
  • Rich text composes with every text style below: stroke, shadows, transform, alignment, wrapping, ellipsis.

5. Variables and localisation Core

<Label text="Hello {name}"/>                         <!-- {name}: variable from the nearest ancestor that set it -->
<Label text="{value:%.2f}"/>                           <!-- number formatting: %f, %d, %i with width/precision -->
<Label text="Score {score:%06d}"/>                     <!-- 000042 -->
<Label text="${PAUSE_MENU_RESUME}"/>                   <!-- localisation key -->
<Label text="${HINT_PRESS}"/>                          <!-- a translated string may itself contain {key} variables -->
<Label>Centered{{braces}}</Label>                      <!-- {{ and }} are literal braces -->
<Panel visible="{hint}"/>                              <!-- attributes can use variables too -->
label->SetVar("name", "Ann");          // text
label->SetVar("score", 42.0);              // numbers keep their value, so {score:%06d} works
page->SetVar("hp", hp);                    // inherited down the tree: every element below sees it
// setting a variable to the value it already has costs one compare
  • A variable is looked up on the element, then up the tree. Components turn their parameters into variables of the instance.
  • Number formats: %f, %d, %i with flags, width and precision (%.1f, %06d). A format on a non-number logs a warning.
  • Localisation runs first, so "Press {key} to open" can be a translated string. ui_pseudoloc makes every string about 35% longer to expose overflow.
  • Elements re-evaluate only the attributes that mention the changed variable.

6. Styles Core

A CSS dialect with its own parser. It reports file:line for every bad declaration.

Selectors

Label            { color: white; }              /* type */
.menu-item       { height: 60px; }              /* class */
#resume          { width: 300px; }              /* id */
.menu .item      { gap: 4px; }                  /* descendant */
.menu > .item    { gap: 4px; }                  /* child */
Button:hover, Button:focus { background-color: #333; }   /* list + states */
.row:focus-within { background-color: var(--kit-row-alt); }
.page:entering { opacity: 0; }                  /* a page that is being pushed */
:root { --accent: #ffcc00; }                    /* custom properties */
.btn { border: 2px solid var(--accent); }

Supported: type, class, id, descendant, child, selector lists. Not supported: sibling and attribute selectors, @media (an unsupported at-rule is skipped with a warning). At-rules that work: @import, @keyframes, @font-face.

Values and units

width: 300px;            /* px: one UI unit = one pixel of the 1080-tall UI target */
width: 50%;               /* of the parent's content box */
font-size: 1.2rem;        /* rem follows the player's text-size setting */
font-size: 2em;           /* em: this element's font size */
height: 10vh; width: 20vw;
width: calc(100% - 48px); /* + - * / on lengths, numbers divide and multiply */
color: #ff8800;           color: #f80;   color: #ff880080;
color: rgb(255, 136, 0);  color: rgba(255, 136, 0, 0.5);   color: hsl(30, 100%, 50%);

Precedence

  1. Values set from C++ on the element (elem->Style())
  2. The style="…" attribute
  3. Stylesheet rules by specificity, then source order
  4. Inherited values (color, font-*, text-*, letter-spacing, line-height, visibility, image-rendering; opacity multiplies down)
  5. Defaults

Custom properties (--name) inherit and are used with var(--name). They are how a theme works.

Component style scope

Rules in a component file are rewritten to match only inside that component, so they never leak. A page can still restyle a component on purpose.

7. Layout Core

Layout is Panorama-style, not flexbox: flow-children chooses how children are placed, sizes are fit-children by default, and fill-parent-flow(n) shares free space.

.column { flow-children: down;  gap: 12px; }          /* children stacked top to bottom */
.row    { flow-children: right; gap: 8px; }           /* left to right */
.grid   { flow-children: right-wrap; gap: 8px; }      /* wraps to the next line */
.stack  { flow-children: none; }                      /* default: children overlay each other */

.fill   { width: fill-parent-flow(1); }               /* takes the free space left in the flow, by weight */
.half   { width: fill-parent-flow(1); }  .rest { width: fill-parent-flow(2); }   /* 1 : 2 */
.fit    { width: fit-children; }                      /* default: as big as the content */
.square { height: 200px; width: height-percentage(100%); }   /* aspect lock */

.centered { horizontal-align: center; vertical-align: center; }
.corner   { horizontal-align: right; vertical-align: bottom; x: -24px; y: -24px; }
.card     { margin: 8px 16px; padding: 12px; min-width: 200px; max-width: 600px; }
.list     { overflow: scroll; height: 400px; }        /* clip + wheel, drag and gamepad scrolling */

Scrolling

overflow: scroll clips the content and scrolls it with the mouse wheel, by dragging the content (touch style, with a little momentum), with gamepad focus (the focused child is scrolled into view), and by the scrollbar. Add scrollbar="true" to get a track and thumb that you style with .scrollbar and .scrollbar .thumb. Drag the thumb, or press the track to jump there. Nothing is drawn when the content fits.

<styles><style>

</style></styles>

9. Motion Core

.card         { transition: opacity 0.3s ease, transform 0.3s cubic-bezier(0.2, 0.8, 0.2, 1); }

  50%  { opacity: 0.4; }
  to   { opacity: 1; }

  • Time is real time: UI motion also runs while the game is paused.
  • A page pushed on a stack starts in :entering and animates to normal. A popped page animates to :leaving and is removed when the transition ends (2 seconds at most).

  • Easings: cubic-bezier(), ease, ease-in, ease-in-out, ease-out, linear, step-end, step-start, steps().

10. Events, actions and code-behind Core

Event attributes hold calls separated by ;. A call is a name with literal arguments. There is no expression language or scripting.

<TextButton text="Play"
            onactivate="PlaySound('GameData/sounds/ui/confirm.wav'); Push('GameData/ui/play.xml')"
            onmouseover="AddClass('#hint', 'show')"
            onmouseout="RemoveClass('#hint', 'show')"/>

<Panel id="page" default-focus="false" oncancel="PlaySound('x.wav')" onload="SetFocus('#play')">
Event attributeFires when
onactivateThe element was activated by confirm, a click or a touch
onblurThe element lost navigation focus
oncancelBack was requested on this page, before the stack handles it
onfocusThe element received navigation focus
onloadOnce, after the element's first layout
onmouseoutThe pointer left the element
onmouseoverThe pointer entered the element

A name resolves in this order: a handler registered with On(name) on the element or the nearest ancestor that has one, then a built-in action, otherwise an "unhandled action" warning (once). Unknown names are reported when the page loads, not only on click.

11. Components and snippets Core

Any XML file whose top element is <Component> defines a new tag. It works like a built-in tag, and components can use components.

<!-- GameData/ui/components/SettingRow.xml -->
<root>
  <Component tag="SettingRow" params="label, hint=''">      <!-- parameters; hint has a default, label is required -->
    <Panel class="row">
      <Label class="label" text="{label}"/>
      <Label class="hint"  text="{hint}" visible="{hint}"/>
      <Children/>                                             <!-- the instance's children go here -->
      <Children slot="footer"/>                               <!-- named slot -->
    </Panel>
  </Component>
</root>
<SettingRow label="${VIDEO_VSYNC}" class="advanced" onchanged="Apply()">
  <ToggleButton id="vsync"/>                                  <!-- slotted children belong to the using file: Find("vsync") works -->
  <Panel slot="footer"><Label text="Needs a restart"/></Panel>
</SettingRow>

<!-- inside the component:  <Raise>  fires the instance's own event:  onactivate="Raise('changed')" -->
  • Parameters (params) become variables of the instance. A missing required parameter or an undeclared attribute is a file:line error.
  • Standard attributes on the instance (id, class, style, visible, events) apply to the component's root; classes merge with its own.
  • Ids are scoped per instance, so two instances can both contain a label. Slotted children belong to the using file. Reach inside an instance with a path: Find("fov_row/label").
  • Discovery. Components under the engine kit and under the game's GameData/ui/ are found at start, no import needed. Elsewhere, add <import>. Two components with one tag, or a component that includes itself, is an error naming both files.
  • Snippets (<snippet>) are file-local components, mainly for rows a page builds from code or a ListView.
  • Frame embeds a whole layout with no parameters; its src can change at run time.
<Frame id="content" src="GameData/ui/kit/pages/sound.xml"/>     <!-- builds a whole layout inside; the page changes with src -->
<Frame snippet="Row"/>                                                <!-- or a snippet / component of this file -->
<!-- code: frame->SetAttribute("src", "GameData/ui/kit/pages/video.xml");  rebuilds the content -->

12. Menu stack, focus and input Core

There is no special page type: any element can be pushed. The stack gives it input, focus, back handling, animation and the host options.

<Panel id="pause" pauses-game="true" hides-hud="true">         <!-- host options: read by the menu stack -->
  <Button id="resume" default-focus="true" onactivate="Back()">...</Button>
  <TextButton text="Settings" onactivate="Push('GameData/ui/kit/pages/settings.xml')"/>
</Panel>

<Panel id="confirm" shows-below="true" close-on-back="true">   <!-- a dialog: the page below stays visible -->
  ...
</Panel>
UiMenus::Push("GameData/ui/kit/pages/pause.xml");     // the main stack; any element can be a page
UiMenus::Stack().Replace("GameData/ui/other.xml");
UiMenus::Pop();   UiMenus::Clear();   bool open = UiMenus::IsOpen();

UiMenus::OnPauseChanged = [](bool paused) { ... };    // the game connects its own pause here
  • Input and focus: only the top page is interactive. Pushing remembers the focused element and popping restores it. default-focus chooses the first focus (for gamepad).
  • Back (ui_cancel, Esc, gamepad B) calls OnBack(), then pops if close-on-back is true.
  • Pages below are hidden unless the page has shows-below="true" (dialogs).
  • Main stack only: pauses-game pauses the game through one hook (UiMenus::OnPauseChanged); hides-hud fades the HUD.
  • Lifecycle hooks on any UiElem: OnPushed, OnShown, OnHidden, OnPopped, OnBack, Tick.

13. Settings binding Core

Variables are one-way. Controls bind both ways to a settings registry with bind="setting:KEY". A page with confirm-changes="true" asks to apply or discard the changes made through bound controls when it is left. A new setting is one registry entry plus one line of markup.

<Slider id="vol" min="0" max="1" step="0.05" bind="setting:audio.master"/>
<ToggleButton id="vsync" bind="setting:video.vsync"/>
<DropDown id="mode" bind="setting:video.window_mode"/>             <!-- items come from the setting -->
<RadioButton group="aa" option="0" bind="setting:video.msaa"/>     <!-- this radio selects value 0 -->
<Label text="{value:%.2f}"/>                                         <!-- sliders expose their value as the variable {value} -->

<!-- page option: leaving with changed bound settings asks "apply or discard?" -->
<Panel confirm-changes="true"> ... </Panel>
UiSettings::Entry e;
e.Key = "game.fov";   e.Type = UiSettings::Kind::Float;   e.Min = 60;  e.Max = 120;  e.Step = 1;
e.Label = "${SETTINGS_FOV}";
e.Get = [] { return Camera::Fov(); };
e.Set = [](double v) { Camera::SetFov((float)v); };
UiSettings::Register(e);          // now bind="setting:game.fov" works in any page

The settings the kit registers are listed in the kit part.

14. Hot reload Core

In builds without DISTRIBUTION, saving a UI file updates the running game. The game runs from a copy of GameData made by the build, so the engine also watches the source files (source/Games/<Game>/GameData), copies changed ones over the running copy and rebuilds every page that depends on them: its XML, imported components, style sheets and their @imports. Structure changes and on… logic count as well as styles.

# Run any non-DISTRIBUTION build, edit a .xml / .css / component file under source/Games/<Game>/GameData/ui and save.
# Within about a second the page on screen is rebuilt from the new files. Kept: slider/drop-down/text values, toggles,
# scroll positions, focus, classes and variables set from code, and attributes the page's code set (the open tab, a Frame's src).
  • Kept: slider, drop-down and text values, toggles and radios, scroll, focus, classes and variables set from code, attributes set from code.
  • Matching after an edit: elements are matched by id, or by position among siblings of the same tag. If you edit an attribute in the file, the file's value wins.
  • Not kept: private fields of code-behind classes and anything built in OnPushed (it is not run again).
  • A broken file keeps the old version on screen and logs the error. A component file that is new since the game started needs a restart. Everything is compiled out of DISTRIBUTION builds.

The kit is a set of ready-made pages and components in GameData/ui/kit/, built only from the core above: pause menu, settings, controls and rebinding, save and load, dialogs. A game gets a complete menu by supplying a theme and a few hooks. Nothing in the core depends on it.
